# Locator `chitall.locator` v1

Locator — устойчивая точная позиция фрагмента в исходном файле книги. Хранится у каждого выделения (и у позиции чтения) в виде JSON. Реализация: `ChitallCore/Sources/ChitallCore/Locator/`, тесты: `LocatorTests`, `ChapterTextTests`.

## Пример

```json
{
  "book": "sha256:3b05d7187e1ec04ffa75d99a61f526a7ad8bdf3edf5e9de09f8cb055a1a2591f",
  "chapter": 1,
  "end": { "offset": 6, "path": "/FictionBook/body[1]/section[1]/p[3]" },
  "format": "fb2",
  "progression": 0.27972,
  "quote": {
    "exact": "Ефим снял шапку и долго смотрел на огни.[1]\n— Соль",
    "prefix": "оял белый туман.\nСтарший возчик ",
    "suffix": " везём, — сказал он стражнику. —"
  },
  "start": { "offset": 15, "path": "/FictionBook/body[1]/section[1]/p[2]" },
  "v": 1
}
```

## Поля

| Поле | Смысл |
|---|---|
| `v` | Версия схемы. Читатель отвергает версии новее своей. |
| `format` | `fb2` (позже `epub`). |
| `book` | `sha256:` + SHA-256 исходных байтов `.fb2` (после распаковки zip), строчные hex. |
| `chapter` | Индекс главы при создании. Информационное поле; для разрешения не используется. |
| `start`, `end` | Точки `{resource?, path, offset}`. `end` исключающий; у позиции чтения `end` отсутствует. |
| `resource` | Файл внутри контейнера (EPUB). Для FB2 не пишется. |
| `progression` | Положение `start` во всём тексте книги, 0…1, 6 знаков. |
| `quote` | `exact` — выделенный текст; `prefix`/`suffix` — до 32 кодовых точек контекста. Только для переякоривания, в экспорт не попадает. |

## Путь

- Шаги — локальные имена элементов без префиксов пространств имён (`fb:p` и `p` — одно и то же).
- Индекс `[n]` — номер среди братьев с тем же именем, с 1 (как в XPath). Корень — без индекса: `/FictionBook`.
- Якорь — абзацный элемент: `p`, `v`, `subtitle`, `text-author`, `date`, `td`, `th`; заголовки — `…/title[1]/p[k]`.
- Текст прямо внутри контейнера (вне абзаца) — `…/text()[n]`, где `n` — номер текстового узла среди всех текстовых детей (включая пробельные), комментарий разделяет текстовые узлы.
- Для внешних инструментов путь переводится в XPath заменой каждого шага `name[n]` на `*[local-name()='name'][n]`.

## Канонический текст элемента

Смещения считаются в нём, правила неизменны внутри версии:

1. Конкатенация всех текстовых потомков (включая `emphasis`, `strong`, `a`, …) в порядке документа. Встроенные картинки текста не дают.
2. Удаляется мягкий перенос U+00AD.
3. Каждая серия XML-пробелов (U+0020, U+0009, U+000A, U+000D) заменяется одним U+0020.
4. Пробел в начале и в конце обрезается.

Остальные символы, включая неразрывный пробел U+00A0, сохраняются. Кодировка файла на канонический текст не влияет: windows-1251 и UTF-8 версии одной книги дают одинаковые locator-ы.

## Смещения

`offset` — число кодовых точек Unicode (scalar values) от начала канонического текста, как в W3C TextPositionSelector и как индексирует `str` в Python. В приложении они переводятся в UTF-16 для `NSRange`; символы вне BMP (`𝔄`, `🧂`) — одна точка в locator-е, две единицы UTF-16 на экране.

Многоабзацный фрагмент: `exact` — тексты абзацев, соединённые `\n`; пустые строки и картинки между ними ничего не добавляют.

## Разрешение

1. **Прямое**: оба пути есть в книге, смещения в пределах текста, `start < end`, и текст по ним совпадает с `quote.exact` → `exact`. Совпадение отпечатка не требуется: переформатированный или перекодированный файл с тем же текстом разрешается точно.
2. **Переякоривание**: иначе ищутся все вхождения `exact` в тексте книги (абзацы через `\n`). Побеждает вхождение с наибольшим совпадением `prefix` (с конца) + `suffix` (с начала), при равенстве — ближайшее к старой `progression` → `relocated`. Короткая цитата (< 12 точек), встречающаяся несколько раз без совпадения контекста, не принимается.
3. Иначе `notFound`: выделение остаётся в «Материалах» со всей провенансной информацией, но не подсвечивается в тексте.

Позиция чтения (без `end`) разрешается по пути, а если путь исчез — по `progression`.
