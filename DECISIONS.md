# Chitall — архитектурные решения

Документ фиксирует, что выбрано, из чего выбирали и почему. Дата исследования: 2026-10-11.
Каждое решение можно пересмотреть, но тогда здесь нужно записать новую причину.

## 0. Контекст на момент решения

| Факт | Значение для проекта |
|---|---|
| Актуальный Xcode — 27.0 (вышел 14.09.2026, Swift 6.4, SDK iOS 27); 27.1 в RC. Требует macOS Tahoe 26.6 и Apple silicon. | Проект пишется под Xcode 16+ формат (buildable folders), проверяться будет в Xcode 27. |
| С апреля 2027 App Store примет только сборки с SDK iOS 27. По сторонним источникам, SDK 27 требует scene-based lifecycle и launch screen. | SwiftUI `App` уже сцено-ориентирован; launch screen генерируется через `UILaunchScreen` в Info.plist. |
| Минимальная версия по брифу — iOS 17. | Нельзя опираться на API iOS 18/26/27 без `if #available`. |
| Среда разработки — Windows. Xcode недоступен. Swift 6.4 для Windows установлен с разрешения пользователя. | Платформонезависимое ядро собирается и тестируется здесь по-настоящему; UI — только на macOS. |

## 1. Рендеринг текста и системное выделение — главный выбор

Требование: нормальное системное выделение (ручки, лупа, меню), своё действие «выделить» в меню, цветная подсветка сохранённых фрагментов, и возможность перевести выделенный диапазон в точную позицию в исходном FB2.

### Рассмотренные варианты

**A. `UITextView` (UIKit) внутри SwiftUI через `UIViewRepresentable` + `NSAttributedString`.**
- Системное выделение, лупа, ручки, «Найти» (`UIFindInteraction`, iOS 16+), Look Up / Translate — бесплатно.
- Выбранный диапазон доступен точно: `selectedRange` (NSRange, UTF-16).
- Своё меню: `textView(_:editMenuForTextIn:suggestedActions:)` (iOS 16+) вызывается и для нередактируемого, но выделяемого текста. Меню собирается из своих `UIAction` + системных.
- Ссылки на сноски: `textView(_:primaryActionFor:defaultAction:)` (iOS 17+) — тап по ссылке-сноске без своих жестов.
- Подсветка — атрибут `.backgroundColor` в `textStorage`, без пересоздания текста и без сброса прокрутки.
- Риск: подменю системы для read-only вида содержит лишние/приватные пункты (известная тема на Apple Developer Forums); решается тем, что свои пункты мы создаём сами, а системные не трогаем и не вызываем через responder chain.

**B. `WKWebView` + FB2, сконвертированный в XHTML (своими силами или через Readium Swift Toolkit).**
- Readium Swift Toolkit: BSD-3-Clause, живой (3.11.0 — июль 2026, 4.0.0-alpha.2 — сентябрь 2026, Swift 6), iOS 15+. Отличная EPUB/PDF-навигация, Decorations API для подсветок, свой Locator (href + progression + text before/highlight/after + cssSelector/CFI).
- Но FB2 Readium не поддерживает: пришлось бы конвертировать FB2 → XHTML и собирать искусственную публикацию. Позиция выделения тогда — DOM Range внутри сгенерированного HTML, её нужно обратно транслировать в путь исходного FB2 через JS-мост. Две модели документа вместо одной.
- Выделение в WebView — системное, но меню и жизненный цикл выделения управляются из JS; отладка двух сред; тяжёлая зависимость (Navigator, Shared, Streamer, ресурсы JS/CSS) ради формата, который она не знает.
- 4.0 сейчас в alpha — завязываться на ломающийся мажор в MVP невыгодно.
- Отдельно: архивный FolioReaderKit (последний push 2020) — мёртвая зависимость, отклонён сразу.

**C. Чистый SwiftUI.**
- `Text` + `.textSelection(.enabled)`: в iOS 17–26 выделяет весь `Text` целиком; в iOS 27 появилось выделение диапазона, но нет API, чтобы прочитать диапазон или добавить своё действие, и выделение не переходит через несколько `Text`.
- `TextEditor(text:selection:)` с `AttributedString` + `AttributedTextSelection` — iOS 26+, это редактор (редактируемость — лишняя и опасная для исходного текста), не подходит под iOS 17.
- Вывод: под iOS 17 SwiftUI-путь не даёт точного диапазона. Остаётся UIKit внутри SwiftUI — бриф это явно разрешает.

**D. Свой рендер на Core Text + `UITextInteraction`.**
- Полный контроль (скруглённые подсветки, пагинация), но самостоятельно реализуются `UITextInput`, геометрия выделения, VoiceOver, лупа, поиск. Это месяцы работы и много мест для ошибок. Отложено как возможная эволюция, если понадобится постраничный режим.

### Решение

**Вариант A: `UITextView` в `UIViewRepresentable`, нередактируемый (`isEditable = false`), выделяемый, на явно собранном стеке TextKit 1 (`NSTextStorage` → `NSLayoutManager` → `NSTextContainer`, тот же результат, что `UITextView(usingTextLayoutManager: false)`, но без неявного переключения движка).**

Почему TextKit 1, а не дефолтный TextKit 2:
- TextKit 2 размечает только видимую область, высота документа оценочная; на форумах Apple многократно описаны прыжки скролла и неточный `scrollRangeToVisible` для длинного текста. Для читалки точное восстановление позиции важнее новых возможностей TextKit 2.
- TextKit 1 стабилен, полностью поддерживается, позволяет `ensureLayout(forCharacterRange:)` и даёт точную геометрию для тап-хит-теста подсветок.
- Рендерим одну главу за раз (см. §2), поэтому стоимость полной разметки ограничена размером главы.
- Стек TextKit 1 собирается явно в одном месте (`ReaderTextView.init`), а геометрия (позиция первой видимой строки, символ под пальцем, прокрутка к смещению) — три небольших метода там же. Переход на TextKit 2 — замена этих мест и прогон чек-листа на устройстве; модель главы и locator-ы от движка разметки не зависят.

Компромиссы: подсветка — прямоугольные фоны (скруглённые — позже через подкласс `NSLayoutManager`); нет постраничного режима (бриф его не требует); Writing Tools не нужны (текст нередактируемый).

## 2. Единица отображения — глава

Весь роман в одном `UITextView` (1–3 млн символов) — дорогая разметка и медленный старт. Поэтому **читатель показывает одну главу** (верхнеуровневую `section` основного `body`), с оглавлением и переходами «предыдущая/следующая». Если у основного `body` ровно одна верхнеуровневая секция с подсекциями — главами считаются её подсекции. Вводная часть body (`title`, `epigraph`) — отдельная глава «Начало». `body name="notes"` — глава «Примечания»: сноски тоже можно читать и выделять, а по тапу на ссылку-сноску показывается всплывающий текст примечания.

## 3. Locator — устойчивая точная позиция выделения

Требование брифа: идентификатор книги + путь XML-узла/главы + символьный диапазон. В брифе не определены единицы символов и правила пробелов — без этого «точная позиция» не воспроизводима. Ниже — уточнение. Полная спецификация: [docs/locator.md](docs/locator.md).

### Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Байтовое смещение в исходном файле | Абсолютно точно для неизменного файла | `XMLParser` не даёт надёжных байтовых смещений (только строка/колонка); ломается при перекодировке и переформатировании; неудобно человеку и ИИ |
| Глобальное смещение символа в тексте книги | Просто | Любая правка до места выделения сдвигает всё |
| Только `progression` (0…1), как минимум у Readium | Устойчиво к правкам | Неточно, не восстанавливает диапазон |
| **Путь элемента + смещение в каноническом тексте + цитата с контекстом** (идея EPUB CFI + W3C Web Annotation TextQuoteSelector) | Точно для того же файла; переживает переформатирование XML и смену кодировки; переякоривается после правок файла | Нужно строго определить канонизацию текста |

### Решение: `chitall.locator` v1

```json
{
  "v": 1,
  "format": "fb2",
  "book": "sha256:9f2c…",
  "chapter": 3,
  "start": { "path": "/FictionBook/body[1]/section[4]/p[12]", "offset": 15 },
  "end":   { "path": "/FictionBook/body[1]/section[4]/p[13]", "offset": 40 },
  "progression": 0.4312,
  "quote": { "exact": "…", "prefix": "…", "suffix": "…" }
}
```

- **Книга** — SHA-256 исходных байтов файла (после распаковки zip). Идентичный файл при повторном импорте = та же книга, выделения возвращаются.
- **Путь** — XPath-подобный путь по локальным именам элементов, индекс `[n]` считается среди одноимённых братьев с 1. Пространства имён игнорируются (в FB2 бывают префиксы и без них). Якорь — ближайший «абзацный» элемент: `p`, `v`, `subtitle`, `text-author`, `td`, `th`, `date` внутри `poem`. Текст вне абзацев — `…/text()[n]`.
- **Смещения** — в Unicode scalar (кодовых точках) канонического текста элемента, как в W3C TextPositionSelector; конец исключающий. Внутри приложения конвертируются в UTF-16 для `NSRange`.
- **Канонический текст элемента** — конкатенация всех текстовых потомков в порядке документа, каждая серия XML-пробелов (U+0020, U+0009, U+000A, U+000D) → один пробел, обрезка по краям, удаление мягкого переноса U+00AD. Многоабзацная цитата склеивается через `\n`.
- **Цитата** `exact` + `prefix`/`suffix` (до 32 символов) — для проверки и переякоривания.

Разрешение: (1) тот же отпечаток и пути существуют, а текст по смещениям совпадает с `exact` → точное попадание; (2) иначе — поиск `exact` в тексте главы/книги, при нескольких совпадениях выбирается лучшее по совпадению prefix/suffix и близости к старой `progression` → «перенесено»; (3) иначе — «не найдено», выделение остаётся в «Материалах», но не рисуется в тексте. Всё это — в ядре и покрыто тестами.

## 4. Разбор FB2

| Вариант | Вывод |
|---|---|
| Foundation `XMLParser` (SAX, libxml2) | **Выбран.** Есть на iOS, Windows и Linux (`FoundationXML`), потоковый, без зависимостей. Внешние сущности по умолчанию не разрешаются (защита от XXE). |
| `XMLDocument` (DOM) | Нет на iOS — только macOS. |
| libxml2 напрямую | C API, ручное управление памятью без выигрыша. |
| Сторонние (SWXMLHash, XMLCoder) | Лишняя зависимость поверх того же `XMLParser`. |

Кодировки: большая часть русскоязычных FB2 объявлена как `windows-1251`. Поддержка не-UTF кодировок в libxml2 зависит от сборки (iconv), поэтому ядро **само** определяет кодировку (BOM → объявление в прологе → эвристика UTF-8), перекодирует в UTF-8 табличным декодером (windows-1251, koi8-r, cp866, windows-1252, iso-8859-1; таблицы сгенерированы из кодеков Python и проверены тестами) и отдаёт парсеру UTF-8 с переписанным прологом. Поведение одинаково на всех платформах.

Понятные ошибки: пустой файл, не XML (строка/колонка из парсера), корень не `FictionBook`, нет `body`, нет текста, неизвестная кодировка, слишком большой файл, zip без FB2 внутри.

## 5. Хранение данных

| Вариант | Плюсы | Минусы |
|---|---|---|
| **SwiftData** | Apple-native (прямо названо в брифе), iOS 17+, `@Query` в SwiftUI | В iOS 17 подтверждённые проблемы со связями/инверсиями и предикатами по optional to-many |
| Core Data | Зрелый | Больше шаблонного кода; та же база под капотом |
| GRDB (MIT) | Предсказуемый SQLite, отличные запросы | Сторонняя зависимость; бриф просит Apple-native |

**Решение: SwiftData, консервативно.** Без связей между моделями (обход известных багов iOS 17): выделение ссылается на книгу по отпечатку `bookFingerprint`, теги — массив строк, locator — JSON-строка в модели плюс денормализованные поля для сортировки. Фильтрация «Материалов» — в памяти (на тысячах выделений это мгновенно). Схема обёрнута в `VersionedSchema` для будущих миграций. Если на устройстве всплывут проблемы, слой `@Model` тонкий и заменим на GRDB без изменения ядра.

Файлы книг — `Application Support/Chitall/Books/<sha256>.fb2` (исходные байты как есть, locator ссылается именно на них), обложки — `…/Covers/`. Настройки чтения — `UserDefaults` (`@AppStorage`). Сети, аккаунтов, аналитики нет.

Удаление книги (бриф: подтверждение + предупреждение): диалог показывает число выделений и даёт выбор — «удалить книгу, оставить материалы» (выделения хранят название книги, автора, главу и цитату, поэтому остаются полноценным материалом и снова привяжутся при повторном импорте того же файла) или «удалить вместе с материалами».

## 6. Модули и абстракция для EPUB

```
ChitallCore (Swift package, без UIKit/SwiftData)  ← тесты: swift test (Windows/Linux/macOS)
  FB2/       кодировки, XMLParser → модель FB2
  Reading/   формато-независимая модель: ReadableBook → Chapter → Block(path, text, runs)
             ChapterText: плоский текст главы + карта блоков в UTF-16 + стилевые отрезки
  Locator/   Locator v1, канонизация, создание/разрешение/переякоривание
  Export/    Markdown и JSON
Chitall (iOS app, SwiftUI + UIKit + SwiftData)    ← тесты: ChitallTests (только Xcode)
```

Ключ к EPUB — **`ReadableBook`**: формато-независимое значение «книга → главы → блоки», у каждого блока `TextAnchor(resource?, path)` и канонический текст. Формат знает только импортёр (`FB2Parser` и `EPUBParser`, §21), который производит `ReadableBook`. `ChapterText`, `LocatorService`, рендер, выделения, «Материалы» и экспорт работают только с этим значением и не знают формата. Ядро не зависит от iOS, поэтому реальные тесты парсинга, locator-а и экспорта выполняются здесь, на Windows.

## 7. Экспорт

- Два файла через системный Share Sheet (`ShareLink` с URL временных файлов): `chitall-materials-YYYYMMDD-HHmm.md` и `.json`.
- Markdown — для чтения человеком и вставки в чат: книга → глава → цитата, мысль, теги, цвет, locator и дата.
- JSON — стабильная схема `chitall.export` v1 с версией, отсортированными ключами, ISO 8601 датами; описана в [docs/export-format.md](docs/export-format.md).
- Экспортируется **только выбранный материал**: текущая выборка «Материалов» (поиск/фильтры) или всё. Контекст `prefix/suffix` из locator-а в экспорт не попадает — это текст книги, который пользователь не выбирал (требование брифа «ничего, кроме выбранного материала»).

## 8. Импорт

- `.fileImporter` (системный Files picker) + «Открыть в Chitall» из Files/«Поделиться» (`CFBundleDocumentTypes`, `onOpenURL`).
- Тип FB2 не зарегистрирован в системе. Объявлен импортируемый тип `com.fbreader.book.fb2` (так его экспортирует FBReader; импорт означает «тип чужой, но мы его читаем») с расширением `fb2`; в рантайме дополнительно используется `UTType(filenameExtension: "fb2")`, чтобы совпасть с тем, что решила система.
- `.fb2.zip` (типичная раздача FB2) поддерживается: минимальный ZIP-ридер в ядре (центральный каталог, методы stored/deflate, проверка CRC-32, защита от слишком больших записей); распаковка deflate — Apple `Compression` (`#if canImport(Compression)`, на Windows/Linux — понятная ошибка). ZIPFoundation (MIT, 0.9.20) рассмотрен; для одного файла внутри архива зависимость избыточна, но станет разумной на этапе EPUB.

## 9. Проект Xcode

- Рукописный `Chitall.xcodeproj` формата Xcode 16+ (`objectVersion = 77`, **buildable folders** — `PBXFileSystemSynchronizedRootGroup`): файлы папок `Chitall/` и `ChitallTests/` подключаются автоматически, не нужно перечислять каждый файл, меньше риска сломать проект руками.
- Ядро подключено как локальный пакет (`XCLocalSwiftPackageReference`).
- XcodeGen/Tuist не используются: оба требуют запуска на macOS и добавляют инструмент; при проблеме с рукописным проектом запасной путь — создать пустой проект в Xcode и перетащить папки (описано в [docs/macos-checklist.md](docs/macos-checklist.md)).
- iOS 17.0 deployment target, iPhone. Ядро — Swift 6 language mode (строгая конкурентность проверена компилятором здесь). Приложение — Swift 5 language mode: строгую конкурентность UIKit/SwiftUI-кода нельзя проверить без Xcode, и не хочется, чтобы первая сборка на Mac упала из-за десятков диагностик; переход на Swift 6 — отдельный шаг после первой сборки.
- Privacy manifest (`PrivacyInfo.xcprivacy`): UserDefaults и метки времени файлов — с указанными причинами, без трекинга.

## 10. Дизайн

Спокойная книжная вещь: тема «Бумага» (тёплый светлый) и «Дерево» (тёмный древесный) + «Как в системе»; шрифт текста — системный serif (New York, поддерживает кириллицу); крупная типографика, регулируемые размер и межстрочный интервал; пять приглушённых цветов выделения с русскими названиями (охра, олива, лазурь, киноварь, сирень). Иконки — только системные SF Symbols и только там, где без них хуже.

## 11. Где бриф сталкивается с реальностью и что сделано

| Бриф | Ограничение | Решение |
|---|---|---|
| «путь XML-узла + символьный диапазон» | Не определены единицы и пробелы; правка файла ломает чистый путь | Строгая канонизация, кодовые точки, цитата с контекстом и переякоривание |
| «Чтение одной главы/длинного текста» | TextKit-разметка всей книги дорогая, TextKit 2 неточен в позиционировании | Глава за раз, TextKit 1 |
| «SwiftData» | Баги связей в iOS 17 | Плоская схема без связей |
| «предупреждает о связанных выделениях» | Удаление выделений уничтожает исследовательский материал | Выбор: оставить материалы или удалить вместе |
| «Экспорт… ничего, кроме выбранного» | Контекст цитаты — текст книги | Контекст хранится для якорения, но не экспортируется |
| FB2 в MVP | В реальности часто `.fb2.zip` и `windows-1251` | Оба поддержаны в MVP |
| «Нормальное системное выделение» | В SwiftUI под iOS 17 нет API диапазона | UIKit `UITextView` внутри SwiftUI |

## 12. План EPUB (этап 2)

1. Контейнер: ZIPFoundation (MIT) или расширение собственного ZIP-ридера; `META-INF/container.xml` → OPF → spine.
2. Каждый XHTML-документ spine разбирается тем же `XMLParser` в те же `Block`-и: `TextAnchor.resource = href` документа, `path` — XPath-подобный путь внутри XHTML (`/html/body[1]/div[2]/p[3]`), канонизация та же. HTML-сущности (`&nbsp;` и др.) EPUB 2 — через предопределённую таблицу.
3. Locator v1 уже имеет поля `format` и `resource` — модели выделений, «Материалы» и экспорт не меняются; JSON экспорта получает `"format": "epub"`.
4. Рендер — тот же `UITextView`: подходит для текстовых книг (основной сценарий исследовательского чтения). Fixed-layout EPUB и сложная вёрстка — не цель; если понадобятся, подключается Readium (BSD-3) как второй рендерер, а его Locator (href + progression + text) конвертируется в наш через тот же `resource` + цитату.
5. Проверка: те же тесты стабильности locator-а на EPUB-фикстурах.

Выполнено в итерации 7 — §21 (план подтвердился; уточнения — там).

## 15. Итерация 2: режим страниц и поиск по книге (2026-10-11)

Отзыв после первой установки на iPhone: чтение главами с прокруткой неудобно, нужны страницы с перелистыванием тапом по краям или сквозная прокрутка всей книги; системный поиск показывал найденное под клавиатурой.

### Как делать страницы — варианты

| Вариант | Вывод |
|---|---|
| **TextKit 1: цепочка контейнеров размером со страницу** | **Выбран.** `NSLayoutManager` сам раскладывает главу по контейнерам и говорит, где кончается страница. Это единственный способ многостраничной вёрстки, который поддерживает TextKit: у TextKit 2 (`NSTextLayoutManager`) несколько контейнеров до сих пор не поддерживаются (ответ Apple на форуме разработчиков). Наш выбор TextKit 1 в §1 здесь окупился. |
| Один `UITextView` со всей главой, прокрутка «по экрану» | Строки режутся пополам на границе экрана, нет настоящей страницы. |
| Core Text (`CTFramesetter`) + свой рендер | Точно, но теряется системное выделение, лупа, меню, VoiceOver. |
| `WKWebView` + CSS-колонки (как Readium) | Другой стек, выделение и locator-ы через JS. Отклонено в §1. |

Реализация:
- **Разметка страниц** (`Paginator`): глава раскладывается через контейнеры размера текстовой области страницы; результат — непрерывные диапазоны символов. Проверяется тестами: страницы покрывают каждый символ ровно один раз, каждая страница помещается в свою область, крупный шрифт даёт больше страниц.
- **Страница** — отдельный обычный `UITextView` только со своими символами (а не общий layout manager на несколько видов: на форумах Apple описаны артефакты отрисовки при таком разделении). Локальное смещение + начало страницы = смещение в главе, так что выделения, locator-ы и подсветки работают без изменений. Абзац, перенесённый на следующую страницу, продолжается без красной строки.
- **Перелистывание**: `UIPageViewController` со сдвигом; свайп или тап по краю (28 % ширины слева/справа), центр — показать/скрыть панели; тап по подсветке открывает её. Страницы идут сквозь главы: после последней страницы главы — первая страница следующей; соседняя глава размечается заранее. Пока выделен текст, свайп отключён, чтобы тянуть ручки выделения.
- **Позиция** — первый символ страницы (тот же caret-locator); при смене шрифта, интервала или поворота экрана книга переразмечается и остаётся на том же тексте.
- В режиме страниц строка состояния не скрывается: иначе меняется размер страницы и текст перескакивает.

### Прокрутка
Остаётся вторым режимом (настройка «Режим чтения»); сквозная прокрутка всей книги — §16.

### Поиск
Свой поиск по всей книге вместо системной панели «Найти»: ядро (`BookSearch`) ищет без учёта регистра и «ё/е» по каноническому тексту, поэтому каждое совпадение — точный `BlockRange`; список с контекстом, тап — переход к месту в любом режиме, совпадение временно подчёркнуто. Работает и для страниц, где системный поиск по одному `UITextView` бесполезен.

### Конкуренты
Обзор и выводы — [docs/competitors.md](docs/competitors.md). Коротко: базовые ожидания (страницы, поиск, поля, переносы, закладки, EPUB) надо закрыть; отличие Chitall — исследовательский поток «цитата → мысль → теги → материал для истории» с точным происхождением.

## 16. Сквозная прокрутка книги и надёжные тапы (2026-10-11)

Отзыв со второй установки: поиск и выделение работают; прокрутка шла главами, а нужна вся книга; тапы у края страницы то срабатывали, то нет.

### Почему тапы «пропадали»
Распознаватель тапа висел на текстовом поле страницы, а у края страницы — поля по 24 pt без текста, плюс заголовок и номер страницы: тап туда не доходил. Кроме того, каждый тап ждал отказа двойного тапа (выделение слова) — задержка, и быстрые тапы склеивались. Теперь:
- зона тапа — вся страница, включая поля, заголовок и номер;
- у краёв (по 30 % ширины) тап срабатывает сразу, а двойной тап там не выделяет слово, а листает ещё раз; в середине тап по-прежнему ждёт двойного (там двойной тап выделяет слово);
- тапы во время анимации не теряются, а ставятся в очередь (до трёх);
- при первом открытии режима страниц показывается подсказка с зонами.

### Сквозная прокрутка — варианты

| Вариант | Вывод |
|---|---|
| Вся книга в одном `UITextView` | Разметка всей книги (миллион символов и больше) — секунды при открытии; с ленивой разметкой TextKit 1 позиции становятся оценочными, теряется точное восстановление места. |
| Одна строка таблицы на главу | Текстовые поля высотой в десятки тысяч точек — риск по памяти, нет переиспользования. |
| **Лента «кусков» глав в `UITableView`** | **Выбрана.** Глава режется тем же `Paginator` на куски примерно в полтора экрана; высота каждого куска измерена точно (`estimatedRowHeight = 0`), поэтому позиции точные и ничего не прыгает. Загружены несколько глав вокруг читателя: следующая добавляется снизу заранее, предыдущая вставляется сверху с компенсацией смещения, дальние выгружаются, когда прокрутка остановилась. |

Компромиссы: выделение не переходит через границу куска (как и через границу страницы); разметка соседней главы занимает главный поток на доли секунды в момент подгрузки (перенос в фон — позже). Проверка: тест «соседние главы подгружаются, а читатель остаётся на том же месте».

## 17. Итерация 3: оформление и навигация не хуже Яндекс Книг (2026-10-12)

Ориентир — скриншоты Яндекс Книг от пользователя: зоны перелистывания по краям (~24 % ширины на всю высоту), темы «Белый / Сепия / Серый / Чёрный / Как в системе», яркость, шрифты, размер −/+, интервалы и поля пресетами, выравнивание по ширине с переносами, сквозные номера страниц, ползунок по книге, «ещё N стр.», закладки.

Решения:
- **Тема страницы отдельно от темы приложения.** Шесть тем страницы (Белый, Бумага, Серый, Чёрный, Дерево, Как в системе); цвета входят в стиль, поэтому смена темы перерисовывает главы, а читалка сама выбирает светлый/тёмный режим для строки состояния и листов. Библиотека и «Материалы» живут в своей теме.
- **Шрифты только с кириллицей:** New York, PT Serif, Georgia, PT Sans, SF Pro (все есть в iOS). Тест проверяет, что каждый шрифт сам рисует кириллицу и не подменяется другим.
- **По ширине с переносами** — `NSParagraphStyle.alignment = .justified` + `hyphenationFactor`, язык из FB2 `lang` (атрибут `NSLanguage`) для правильных русских переносов. Заголовки, стихи и подписи не переносятся.
- **Пресеты вместо ползунков:** размер −/+, три интервала, три поля — быстрее и предсказуемее при чтении одной рукой.
- **Яркость** меняется только в читалке и возвращается системе при закрытии книги или уходе приложения в фон.
- **Сквозные номера страниц** («118 из 294») — фоновый проход разметки всей книги теми же рендером и пагинатором, что и страницы; пока проход не закончен, показывается номер внутри главы. Тест сверяет фоновые числа с реально показанными страницами.
- **Ползунок по книге** переходит по доле текста (`ReadableBook.position(atProgression:)`, обратная к `progression(of:)`; тест — на каждом абзаце).
- **Закладки** — новая модель; хранилище переходит на схему V2 лёгкой миграцией (только новая сущность; модели V1 заморожены). Тест открывает настоящее хранилище V1 с выделением и проверяет, что после миграции всё на месте.
- **Лучше, чем у Яндекса, для исследования:** пункт «Тег» прямо в меню выделения (цитата с тегом одним тапом), «Содержание» с вкладками «Оглавление / Закладки / Выделения», экспорт материалов текущей книги из читалки.

## 18. Итерация 3.1: замечания с телефона (2026-10-12)

- **Панель «Оформление» рисуется цветами темы читалки**, а не системными (`.primary`, `Color.secondary`): лист открывается в схеме приложения, и на «Чёрном»/«Дереве» тёмные подписи терялись на тёмном фоне. Теперь текст, значки, обводки и подсказка берут цвета `ThemeColors`, а `colorScheme` листа задаётся темой.
- **Сноски — карточка снизу, как в Яндекс Книгах:** цвета страницы и шрифт книги, крупный номер, крестик, высота по тексту (длинная сноска прокручивается, лист можно растянуть). Скобки `[23]` в текст не добавляем — карта символов отображения должна совпадать с текстом книги (locator); вместо этого номер чуть крупнее обычного верхнего индекса и с пунктирным подчёркиванием. Тап засчитывается и рядом с номером (±14 pt): по крохотной цифре трудно попасть.
- **Процент — целым числом с округлением вниз;** «100 %» только когда на экране конец последней главы. В экспорте остаётся точность до десятых (там это место цитаты).
- **Закладки в «Прокрутке»:** участок ленты — то, что сейчас на экране; положение сообщается модели при каждой смене верхней или нижней строки (раньше — только после остановки прокрутки; тап, который останавливает инерцию, остановкой не считается — вероятная причина, почему закладки в ленте «не работали»). Значок заполнен, пока отмеченная строка на экране. Дополнительно: ленточка на правом поле у отмеченной строки и отметки всех закладок над ползунком. Позиции закладок кэшируются по карте символов главы без отрисовки (раньше каждая закладка отрисовывала свою главу).

## 19. Итерация 4: «Лёгкое чтение» — дислексия и концентрация (2026-10-20)

У пользователя лёгкая дислексия, иногда трудно сосредоточиться. Принцип: всё — настройки, а не жёсткие правила. При дислексии людям помогает разное, значения подбираются на своём телефоне.

- **Переключатель «Лёгкое чтение»** (в «Оформлении», сверху) — пресет поверх обычных настроек: по левому краю без переносов, межбуквенный интервал «Шире» (0,08 em), межстрочный «Очень свободный» (1,85), белый фон → «Бумага». Включён, пока выполнены все условия; если поставить ещё шире, он остаётся включённым. При выключении возвращаются прежние настройки (их сохраняем при включении), но тема, выбранная за это время, остаётся.
  - Межбуквенный интервал — единственная типографская мера с хорошими доказательствами (Zorzi et al., 2012, PNAS: меньше ошибок, быстрее чтение у детей с дислексией). Сделан через `.kern`, ступени 0 / 0,04 / 0,08 / 0,12 em. Пробелы получают ×2,5 от межбуквенного, иначе слова слипаются (в исследовании расстояние между словами тоже росло). Меняются только атрибуты: карта символов и цитаты не затронуты.
  - По левому краю — без переносов: при выравнивании по ширине пробелы неровные, а переносы рвут слово (рекомендации British Dyslexia Association: по левому краю, без выравнивания по ширине). Раньше режим «не по ширине» оставлял немного переносов, теперь их нет.
  - «Колонка уже» отдельно не нужна: на iPhone строка уже ~35–45 знаков, это меньше рекомендуемых 60–70. Ширину по-прежнему задают поля.
- **Шрифты.** Atkinson Hyperlegible Next проверен и **отклонён**: в нём нет кириллицы (проверено по таблице cmap). Взяты:
  - **Andika** (SIL, OFL 1.1) — шрифт для начинающих читателей и людей с трудностями чтения: различимые б/д/в, I/l/1, полная кириллица, 4 начертания.
  - **OpenDyslexic** (OFL 1.1) — по исследованиям польза не доказана (Wery & Diliberto, 2017), оставлен как вариант по вкусу. Кириллица полная. Взяты только обычный и жирный: у курсивных файлов неверные метаданные (macStyle/fsSelection не помечены как italic), iOS путает их с обычным начертанием. Для курсива — программный наклон (`.obliqueness` 0,18) у любого шрифта без italic.
  - При включённом «Лёгком чтении» эти шрифты стоят первыми в ряду шрифтов.
- **Линейка фокуса** — только в «Прокрутке». Линия чтения — на 30 % видимой высоты. Абзац, который её пересекает, остаётся ярким (не больше двух строк выше и ниже текущей строки, чтобы длинный абзац тоже вёл взгляд), остальная лента приглушена полупрозрачным фоном темы. Слой не перехватывает касания: выделение работает как обычно. В «Страницах» не сделана: там нет движения, за которым линейка могла бы идти, а тап уже занят листанием и панелями.
- **Время до конца главы** — по собственному темпу: слова, пройденные между перелистываниями или прокруткой вперёд, делённые на время. Отбрасываем меньше 20 слов или 3 с, а также темп вне 40–700 слов/мин — это прыжок, просмотр или пауза. Пока прочитано меньше 300 слов, к измерению подмешивается 150 слов/мин. Дальше — скользящее среднее примерно по последним 2000 словам. Темп общий для всех книг (UserDefaults). Подсчёт слов — индекс начал слов по главе (бинарный поиск, логика в ядре и тестируется на Windows). Время показано в подвале страницы («118 из 294 · ≈ 6 мин до конца главы») и в «Прокрутке» под ползунком.
- **Напоминание о паузе** — 10/15/20/30 мин или нет: тихая карточка внутри книги («Ещё N мин» / «Хорошо»), без звука и системных уведомлений (не нужно разрешение, не отвлекает вне чтения).
- **«Где я остановился»** — при открытии книги на сохранённом месте (не при переходе к выделению) карточка: последние ~220 знаков перед местом (с начала предложения, если оно рядом) и последнее выделение с мыслью. Исчезает по тапу или при первом перелистывании или прокрутке. Отключается в настройках.
- **Чистый экран** — панели прячутся при первом перелистывании или прокрутке пальцем (не при переходах из оглавления или ползунка), без названия главы над текстом. Строка статуса скрыта постоянно, чтобы размер страницы не менялся при показе панелей. Тап в центр — показать панели.
- **Не делаем:** «бионическое чтение» (жирные начала слов) — исследования пользы не нашли. Чтение вслух с подсветкой слова (`AVSpeechSynthesizer`, офлайн) — следующая итерация.

## 20. Итерация 5: «Чтение и слова» (2026-10-21)

Первый отзыв по итерации 4: напоминание о паузе не нашлось — оно было внизу «Оформления». Чтение вслух пользователь не выбрал — не делаем.

- **Таймер паузы на нижней панели книги** — кнопка с таймером между закладкой и «Оформлением». Меню: 10 / 15 / 20 / 30 мин, «Начать заново», «Выключить»; рядом со значком — сколько осталось («12 мин», округление вверх, «пора», когда время вышло), значок акцентного цвета, пока таймер идёт. Выбор сохраняется (тот же ключ `reader.sessionMinutes`) и запускается в следующей книге; «Выключить» выключает и на будущее. В «Оформлении» вместо спрятанного выбора — одна строка «кнопка с таймером на нижней панели»: два места для одной настройки только путают. Логика (`PauseTimer`: конец, остаток, подписи) — в ядре, тесты на Windows; часы — `ReaderModel.now`, их подменяют тесты приложения. Карточка «Вы читаете уже N мин» осталась прежней: тихо, без звука и системных уведомлений.
- **«Значение» слова** — пункт в меню выделения сразу после «Выделить» и «Мысль…». «По долгому тапу» — это системное выделение слова долгим нажатием: меню открывается само, и «Значение» видно без прокрутки меню. Отдельный жест на долгий тап не делаем: он отнял бы у читателя выделение, на котором держится всё приложение.
  - Словарь — `UIReferenceLibraryViewController` (системные словари iOS: скачиваются один раз, дальше офлайн, без ключей и серверов). Альтернативы: свой словарь в бандле (большой, лицензии старых толковых словарей неочевидны) и пункт «Найти» из системного меню (он остаётся, но лезет в интернет, Siri и веб).
  - Перед поиском слово очищается (`LookupTerm` в ядре): кавычки, знаки по краям, номера сносок «[2]», ударения (U+0301 — часто в исторических текстах), мягкие переносы. Фраза до 4 слов — да, предложение — нет (пункта нет).
  - `dictionaryHasDefinition(forTerm:)` проверяет и исходное слово, и строчное («Казённую» в начале фразы). Нет статьи — своя карточка: «Настройки → Основные → Словарь → «Русский»» и кнопка «Открыть словари» (системная карточка с «Управлять словарями», где словарь скачивается на месте). Системную карточку показывает UIKit поверх экрана, а не SwiftUI-лист: у неё своя кнопка «Готово», о которой SwiftUI не узнал бы.
  - Старинного слова может не быть и в скачанном словаре — карточка об этом говорит. Свой исторический словарь — возможная доработка, если понадобится.
- **Режим «По абзацу»** — третий в переключателе «Страницы / Прокрутка / По абзацу». На экране только текущий абзац, шрифт ×1,25 от выбранного (не больше 40 pt), чуть выше середины; длинный абзац прокручивается. Следующий — тап у правого края или свайп влево, предыдущий — у левого края или свайп вправо, дальше через главы; смена — мягкое растворение 0,18 с, без «листа», за которым надо следить глазами. Тап в центр — панели; выделение — как везде (пока текст выделен, свайпы выключены).
  - Экран («шаг») — диапазон в координатах `ChapterText` из целых блоков (`ParagraphSteps` в ядре, тесты на Windows). Поэтому позиция чтения, выделения, мысли, закладки, поиск, ползунок, темп чтения и «≈ N мин до конца главы» работают через те же `ReaderModel.didShowPage`, `createHighlight`, `toggleBookmark`, что и в «Страницах»: для модели абзац — это страница.
  - Склейки, чтобы экран читался целиком: заголовок — со следующим блоком; подпись и дата — с тем, что подписано; строки одной строфы и ячейки таблицы — вместе (до ~600 знаков); абзацы одного эпиграфа — вместе; подряд идущие короткие реплики (каждая < 60 знаков) — на одном экране, пока он короче 200 знаков. Иначе диалог превратился бы в десятки касаний по «— Да.».
  - Внизу экрана «абзац 5 из 40 · ≈ 6 мин до конца главы», на панели — «абзац 5 из 40»; закладка — ленточка вверху справа. «Чистый экран» убирает название главы.
- **«Мысль голосом»** — кнопка «Надиктовать» над полем мысли в редакторе выделения. `SFSpeechRecognizer` для `ru-RU`, только на устройстве (`requiresOnDeviceRecognition = true`), с расстановкой знаков (`addsPunctuation`), промежуточные результаты видны сразу. Надиктованное добавляется к написанному отдельным предложением (`DictationText.merge` в ядре: точка и заглавная буква, после запятой или тире — продолжение фразы) и не удваивается, пока растёт распознанный текст.
  - Если iPhone не распознаёт русский без интернета (`supportsOnDeviceRecognition == false`) — честная подсказка про микрофон на клавиатуре; на сервер Apple голос не отправляем, хоть это и было бы проще. Нет разрешения — подсказка, где его дать.
  - Разрешения `NSMicrophoneUsageDescription` и `NSSpeechRecognitionUsageDescription` — в `Config/Info.plist`; `tools/check_project.py` теперь проверяет, что они есть (без них iOS закрывает приложение при первом нажатии на микрофон).
  - Новый `SpeechAnalyzer`/`SpeechTranscriber` (iOS 26) отложен: проект поддерживает iOS 17, а русского в объявленном при запуске списке языков SpeechTranscriber не было (проверять надо по `supportedLocales` на устройстве; в симуляторе список пуст). Можно перейти позже за `if #available`.
  - Замыкания аудиовхода и распознавателя создаются вне главного актора: они вызываются на своих потоках, и замыкание, привязанное к главному актору, на них упало бы.
- **Проверка:** логика — в ядре (тесты на Windows); тесты приложения: таймер по подменённым часам; «Значение» в меню слова и не в меню предложения, строчный вариант слова, карточка без словаря; режим «По абзацу» — один абзац на экране, переход вперёд/назад через главу, позиция и переход по месту, выделение с мыслью, закладка; голос — разрешения в Info.plist, добавление к мысли без удвоения, подсказка без распознавателя. Живой микрофон, системный словарь и свайпы на симуляторе не проверить — только на iPhone.

## 21. Итерация 7: EPUB (2026-10-21)

Макар решил делать EPUB раньше итерации 6 (уверенность, типы тегов, доски). PDF и TXT — отдельно, потом.

- **Свой разбор, а не Readium.** Проверено актуальное состояние: Readium Swift Toolkit — 3.11.0 (BSD-3-Clause, активно развивается; навигатор на `WKWebView`, разбор — `ReadiumStreamer`), ZIPFoundation (MIT). Readium отклонён снова, как в §1 и §12: его навигатор рисует HTML в веб-вью, а у нас всё держится на `UITextView` с точной картой символов. Одного `ReadiumStreamer` мало: он даёт `Publication` (манифест, порядок чтения, оглавление), а превращать XHTML в наши блоки с путями и каноническим текстом всё равно пришлось бы самим. При этом он тянет несколько пакетов (ZIP, XML/HTML-парсеры, криптография для LCP), не собирается и не тестируется на Windows и сделал бы ядро зависимым от iOS. Свой разбор — продолжение того, что уже было для FB2: `ZipArchive` + `XMLParser` + те же `Block`; сторонних зависимостей по-прежнему нет. Fixed-layout EPUB, комиксы и сложная вёрстка — не цель; если понадобятся, Readium подключается вторым рендерером, а его Locator (`href` + `progression` + `text`) переводится в наш через `resource` + цитату (§12, п. 4).
- **Контейнер.** `META-INF/container.xml` → OPF (`rootfile` с `application/oebps-package+xml`; запасной путь — первый `.opf` в архиве). EPUB узнаётся по содержимому, а не по расширению: ZIP с `mimetype` или `container.xml` и без `.fb2` внутри. Пути — сначала точно, потом без учёта регистра (неряшливые href-ы встречаются); `%20` раскодируется — `resource` всегда настоящее имя файла в ZIP.
- **DEFLATE на Windows.** `Compression` есть только у Apple, а почти все EPUB сжаты. Добавлен свой распаковщик RFC 1951 (`PortableInflate`, ~200 строк: stored, фиксированный и динамический Хаффман) — только для не-Apple платформ, как своя SHA-256. На iPhone по-прежнему `Compression`. Тесты сверяют оба с потоками zlib всех трёх видов; заодно `.fb2.zip` со сжатием теперь проверяется и на Windows.
- **DRM.** `META-INF/encryption.xml` с любым алгоритмом, кроме обфускации шрифтов (IDPF `…/2008/embedding`, Adobe `…/pdf/enc#RC` — это не DRM, текст читается), или `META-INF/license.lcpl` (Readium LCP) → «Книга защищена DRM: её текст зашифрован. Chitall открывает только книги без защиты — файлы, купленные без DRM, или свои собственные». Ничего не расшифровывается и не обходится.
- **Метаданные OPF.** `dc:title` (с `title-type=main`, если названий несколько); `dc:creator`/`dc:contributor` с ролью из `opf:role` (EPUB 2) или `<meta refines … property="role">` (EPUB 3): `aut` — авторы, `trl` — переводчики, остальные (иллюстратор, редактор) — нет; язык (для переносов), издатель, дата и год, темы, ISBN (`urn:isbn:` или `opf:scheme="ISBN"`), уникальный идентификатор, серия (EPUB 3 `belongs-to-collection` + `group-position` или Calibre `calibre:series`/`series_index`), аннотация из `dc:description` (HTML в ней превращается в абзацы). Имя автора — одной строкой (`Person.firstName`): `file-as` не разбираем, интерфейсу нужна только строка.
- **Обложка:** `properties="cover-image"` (EPUB 3) → `<meta name="cover">` (EPUB 2) → картинка с «cover» в id или имени. В библиотеку сохраняется тем же `writeCover` (JPEG/PNG/GIF). Страница-обложка из spine остаётся первой «главой» с картинкой — как в других читалках.
- **Главы = документы spine** (включая `linear="no"`, по порядку). Название — из оглавления: EPUB 3 `<nav epub:type="toc">`, иначе NCX EPUB 2. Пункт без `#` (или ведущий в начало документа) — название главы; если таких несколько (часть и глава в одном файле) — последний, более глубокий. Пункты с `#id` внутри документа — подпункты «Содержания» (`TOCEntry`). Нет пункта — первый заголовок `h1…h6`; глава из одной картинки — «Обложка» или «Иллюстрация»; иначе «Раздел N». Сломанное оглавление стоит только названий глав, не книги.
- **XHTML → блоки** (`XHTMLBlockBuilder`). Элемент — пропускаемый (`head`, скрипты, стили, сноски-`aside`), картинка (`img`, `svg` с `image`), блочный (block-level HTML) или строчный. Блочный элемент только со строчным содержимым — один абзац с путём самого элемента (`/html/body[1]/div[2]/p[3]`; `<div class="p">` вместо `p` тоже работает). Блочный с блочными детьми — контейнер, а строчный текст между его блоками — абзац с якорем на первом узле (`…/text()[2]`), как «бродячий» текст в FB2. `h1…h6` — заголовки уровней 1…6, `td`/`th` — ячейки, `blockquote` — цитата, `epub:type`/класс «epigraph» — эпиграф, класс «poem/verse/stanza» — стихи. Строчные: `em/i/cite` — курсив, `strong/b` — жирный, `s/del`, `sub`, `sup`, `code`, плюс `style="font-style: italic"` и `font-weight: bold`. CSS-классы не разбираем (`<span class="italic">` останется прямым): разбор CSS ради редкого случая не окупается.
- **Разрывы строк.** `<br/>` склеился бы пробелом — стихи и подписи потеряли бы строки. В EPUB он даёт U+2028 (разрыв строки внутри абзаца: `UITextView` переносит, отступ первой строки не повторяется), пробелы вокруг отбрасываются. Это расширение правил канонического текста только для EPUB (флаг `keepsLineBreaks`); FB2 канонизируется как раньше — старые locator-ы не затронуты. `<p>&nbsp;</p>` и `<hr/>` — пустая строка.
- **Сущности HTML.** XHTML 1.1 в EPUB 2 полон `&nbsp;`, `&mdash;`, `&laquo;`, а объявлены они только во внешнем DTD, который мы не грузим (офлайн, без внешних сущностей). Перед разбором 248 именованных сущностей HTML 4 заменяются числовыми ссылками (`HTMLEntities.swift` генерирует `tools/gen_html_entities.py` из `html.entities` Python); неизвестное имя становится видимым текстом, а не ошибкой всей книги. Документ со своими `<!ENTITY>` их сохраняет.
- **Сноски и ссылки.** Ключ цели — `resource#id` (`OEBPS/Text/ch1.xhtml#n1`), документа целиком — `resource`; это те же `idTargets` и `notes` в `ReadableBook`, поэтому `ReaderModel.target(of:)` и карточка сноски не изменились. Сноска — ссылка с `epub:type="noteref"` (EPUB 3) или, в EPUB 2 без разметки, ссылка на `#id`, похожая на сноску: в `<sup>`, с классом «note» или с коротким номером «3», «[12]», «*». Текст карточки — блоки элемента-цели (для `<a id>` внутри абзаца — весь абзац), без ссылки «↩». Обратные ссылки из примечаний (Calibre: `<p><a id="n1" href="…#r1">[1]</a> Текст</p>`) — не сноски, а обычный переход в текст: их цель — ссылка-номер посреди абзаца, а примечание начинается со своего номера. Внешние ссылки (`http:`) не сохраняются — приложение офлайн. В URL ссылки цель кладётся в путь через `percentEncodedPath`, чтобы `#` и пробелы не терялись.
- **Locator.** `resource` — путь файла в ZIP, `path` — внутри XHTML, смещения — кодовые точки канонического текста, `format: "epub"`, `book` — SHA-256 всего `.epub` (хранится сам файл, на диск ничего не распаковывается). Модели SwiftData, «Материалы», экспорт, поиск, закладки, позиция чтения и все три режима работают без изменений через `ChapterText`/`ReaderModel`. Перепакованный EPUB (другое сжатие, другой отпечаток) разрешается точно, правленый — переякоривается по цитате (тесты).
- **Приложение.** Файл хранится как `<sha256>.epub`; формат определяется по расширению сохранённого файла — схема SwiftData не меняется (новая версия схемы будет в итерации 6, две подряд ни к чему). `BookImporter.readStoredBook` открывает и FB2, и EPUB. «О книге» — строка «Формат: EPUB / FB2 / FB2 из архива ZIP». `Info.plist`: `org.idpf.epub-container` в `CFBundleDocumentTypes` (системный тип, объявлять не нужно) — EPUB появляется в «Открыть в Chitall»; `check_project.py` это проверяет. В выборе файла — `.epub`.
- **Тестовые книги** — только свои: `tools/make_epub_fixtures.py` пишет 8 EPUB (EPUB 3 и EPUB 2 со всеми случаями выше, перепакованный, правленый, с DRM, с обфускацией шрифтов, со сломанным XHTML, без `container.xml`) и потоки DEFLATE; в тестах приложения EPUB собирается в памяти. Ничего не скачивалось.
- **Ограничения:** нет встроенных в абзац картинок, CSS-оформления классами, таблиц сеткой, fixed-layout, аудио/видео, MathML. SVG-картинки не рисуются (`UIImage` их не читает). Очень большой XHTML-файл — одна большая глава (оглавление внутри работает, разбивки по заголовкам нет).
